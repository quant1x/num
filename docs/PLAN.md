# 跨语言落地任务计划表

> 本文档是 **num / pandas 多语言推进** 的排期基准：模块怎么切、谁依赖谁、按什么顺序做。
> 模块文档（功能级 `.md`）按 [MODULE-TEMPLATE.md](MODULE-TEMPLATE.md) 落在代码同目录；本文档只回答"做什么、先后顺序、做完怎么算完"。
> 进度变化时更新 §4 的状态列，不重写 §1 ~ §3 的口径。

## 1. 目标与判据

**目标**：同一份语义，在 Python / C++ / Rust / Go 四门语言里各自**原生、纯正**地实现，语言之间只通过**统一数据格式**（CSV 为基线）交换，不通过解释器嵌入或 ABI 绑定。

**六条硬判据**：

1. **原生实现，不做绑定层**：每门语言用自己的语言习惯把算法写全 —— 不内嵌 Python 解释器、不以"C 库 + FFI 壳"作为交付形态。`dll` 的 ABI 稳定性、各语言调用约定、异常与错误码翻译都是纯成本，换不到语义保证。
2. **语义唯一，签名可差异**：语义以 Python（np / pd）研究口径为准；C++ / Rust / Go 各自按语言习惯命名（Go 导出、Rust snake_case、C++ namespace），**但最小参数集必须一致** —— 周期、序列、平滑因子这类业务必需参数不得增删、不得改名换义；结果必须一致，由 fixture 判定。
3. **一个功能一个权威口径**：每个功能只允许存在一套被 fixture 卡住的语义。禁止同一功能出现两套互不校验的算法（`formula.WMA` 与 `Series.Rolling().WMA()` 并存的形态即违例）。
4. **可机械验证**：跨语言一致性只认 golden fixture 逐元素对拍，不认人眼比对。浮点口径见 §3.3。
5. **交付面纯净（IP 保护）**：生产交付只给编译产物（Go 单二进制、C++ / Rust 静态库与头文件）。Python 只出现在研究侧，**不进入客户交付链路** —— 解释型语言的源码即算法本身，加密与打包不构成保护。
6. **格式取最小公约数**：语言间交换只走**通用文件格式**，表头只能是纯列名，不得携带类型注解、命名空间或库私有方言（详见 §2.3 `D1`）。绘图同理：1x 只产出标准格式数据，图形由使用方或研究侧负责。

**明确不做**：不重造 DataFrame / ndarray 结构；不把 Python 生态当作运行时依赖；不引入自带私有表头方言的 dataframe 库充当交换层；不在 Go 侧为追 C++ 数值路径而牺牲可用性。

> **为什么不做绑定（决策记录）**：绑定等价于把"必须是 Python 环境"钉进交付物。只会 Go 的使用者没有 Python 运行时，也没有 ML 生态可用；客户拿到的若是 Python 源码，等于算法裸奔。异构实现的成本高，但它换来的是每门语言都能独立部署、独立交付、独立保护。

## 2. 模块划分

路径均相对各仓库根；`num` = `github.com/quant1x/num`，`pandas` = `github.com/quant1x/pandas`。

### 2.1 契约层（C）—— 唯一事实源

| ID | 模块 | 载体 | 语言 | 交付物 | 现状 |
| --- | --- | --- | --- | --- | --- |
| C1 | 符号与签名契约表 | `num/tests/contract/NAME-MAP.tsv` | 与语言无关 | 每行一个功能：语义名、**最小参数集**、默认值、NaN 约定、返回形状、各语言符号名、**权威实现语言** | 已落地 |
| C2 | fixture 生成器 | `num/tests/fixtures/gen/*.py` | Python（研究侧） | 由 np / pd 生成输入与期望输出，落 `<模块>/<用例>.npz` | 已落地 |
| C3 | fixture 读取器 | `num/tests/fixtures/read_{cpp,rs,go}` | C++ / Rust / Go | 各语言最小 npz 读取，只依赖标准库与已有依赖 | 已落地 |

`C1` 的 **最小参数集** 列是签名差异的边界：语言之间允许命名风格不同、允许各自追加可选参数（如并行度、缓冲区），但最小参数集内的参数个数、顺序语义、取值约束必须逐条对位。

### 2.2 内核层（N）—— num 的数值本体（每语言原生实现）

| ID | 模块 | 载体 | 语言 | 交付物 | 现状 |
| --- | --- | --- | --- | --- | --- |
| N1 | 标量与类型边界 | 根包 + `kind/` | Go / C++ / Rust | `DType` ↔ f32 / f64 / i8..u64 映射、NaN / ±Inf / ±0 约定 | Go 已落地，C++ 部分，Rust 部分（fixture 子集） |
| N2 | 逐元素算子 | 根包 + `x32/` + `x64/` | Go / C++ / Rust | 算术、比较、逻辑、取整、三角 | Go 已落地，C++ 部分，Rust 部分（fixture 子集） |
| N3 | 归约族 | 根包 + `internal/functions/` | Go / C++ / Rust | sum / mean / std / var / min / max / argmin / argmax | Go 已落地，C++ 部分，Rust 部分（fixture 子集） |
| N4 | 窗口与滚动族 | `internal/functions/` | Go / C++ / Rust | rolling / apply / min_periods / 移动统计 | Go 已落地，C++ 部分（缺 min_periods），Rust 部分（fixture 子集） |
| N5 | 向量化内核 | `x32/*_amd64.s`、`*_arm64.s` | Go / C++ | `Xxx_AVX2_F32/F64` 双架构实现；C++ 走 xsimd | Go 已落地 |
| N6 | 向量与容器 | `vectors/`、`binary/` | Go / C++ / Rust | 序列裁剪、对齐、字节序读写 | Go 已落地，Rust 部分（fixture 子集） |

**语言分工**（不是降级，是承载不同交付面）：

| 语言 | 角色 | 承载什么 | 不承载什么 |
| --- | --- | --- | --- |
| Python | 研究侧 | 因子探索、算法定型、绘图、高阶因子先研 | 客户交付、生产运行 |
| Go | 工程侧一等 | 工具链、服务、数据管道、单二进制部署；数值实现完整可用 | 极致算力、ML 生态（实事求是：该领域 Go 生态薄弱） |
| C++ | 生产核心 | 性能敏感内核、可嵌入库、无 GC 运行时 | 上层业务编排 |
| Rust | 生产核心 | 内存安全的生产内核、单二进制交付 | 上层业务编排 |
| Zig / Java | 扩展 | 按客户栈补齐 | 主路径 |

### 2.3 交付面（D）—— 语言之间怎么对接

| ID | 模块 | 载体 | 语言 | 交付物 | 现状 |
| --- | --- | --- | --- | --- | --- |
| D1 | 交换格式规范 | `docs/DATA-FORMAT.md` | 与语言无关 | CSV 基线：UTF-8 无 BOM、逗号分隔、**表头只写纯列名**、缺失值空字段、时间 ISO 8601、数值用十进制文本（可选科学计数）。可选扩展：JSON Lines、二进制（含 dtype 与 shape 头） | 已落地 |
| D2 | 各语言 CSV 读写 | Go `encoding/csv`；C++ 最小 reader/writer；Rust `csv` crate | Go / C++ / Rust | 各语言原生读写，互读互写结果一致 | 已落地（Rust 为 `tests/io/rs` 工具，生产 crate 待 M4） |
| D3 | 编译产物分发 | 各仓库发布物 | Go / C++ / Rust | Go 单二进制；C++ / Rust 静态库 + 头文件 + 版本号 | 已落地（Go 由 build info、C++ 从 tag 派生；Rust 版本由 autochangelog 改写） |
| D4 | 绘图边界 | 无代码 | — | 1x 只产出 `D1` 格式数据；图形由使用方（研究侧 Python、业务侧前端）自行绘制 | 约定完成 |

**表头红线**：`D1` 的列名只允许标识符（字母、数字、下划线）。任何形如 `price:double`、`close@f64`、命名空间前缀的写法都属于库私有方言，禁止进入交换层 —— 一旦写进文件，Python / Go 的通用 CSV 读取器就都得为它写特例，跨语言交换立刻失效。

**同源复用（可选，非交付路径）**：同一仓库同一发布版本内，Rust 可以静态链接 C++ 源、Go 可以 cgo 调静态库以省一份实现；但这属于仓库内部优化，不对外承诺 ABI 兼容、不作为下游集成方式。对外只认二进制与数据文件。

## 3. 依赖关系

### 3.1 依赖图

```text
① 语义与内核
C1 ─► C2 ─► C3 ─► N1 ─► N2 ─► N3 ─► N4
                        │      │
                        │      └─► N5
                        └─► N6

② 语言落地（三条线彼此独立，都只依赖 ①）
N1..N4 ─► B1（Go） / B2（C++） / B3（Rust）
C1 ─► Rust crate ─► B3
N1..N5 ─► G2（Go 完整数值路径）

③ 数据交换与验收
C1 ─► D1 ─► D2 ─► B5 / M2 / M3
C2 ─► M1 ─► M3 ◄─ M2
D3 ◄─ N1..N5 / G2（内核完成即可发布）
G1 ◄─ G2
```

### 3.2 依赖边说明

| 前驱 | 后继 | 为什么必须在前 |
| --- | --- | --- |
| C1 | C2 / C3 / D1 | 语义名与最小参数集先定；`D1` 的列名必须能对上 `C1` 的语义名，否则文件格式与代码符号两套命名 |
| C1 | Rust crate（B3 载体） | Rust 侧按契约表建 crate，不等 C++ 完成，可与 N5 并行 |
| C2 | C3 | 生成器先产出样本，读取器才有东西可读 |
| C3 | N1 ~ N6 | 没有读取器，各语言无法消费同一批 fixture，"一致"无从判定 |
| N1 | N2 / N3 / N6 | 类型映射与 NaN 约定是所有算子的公共前提 |
| N2 / N3 | N5 | 向量化是逐元素与归约的加速路径，标量语义未定不写 intrinsics |
| N3 | N4 | 滚动族在每个窗口内复用归约实现 |
| N1 ~ N4 | B1 / B2 / B3 / B6 | 公式族是内核的组合层，内核未定型则公式只能各自重写一遍 |
| N1 ~ N5 | G2 | Go 数值路径由 Go 自己的内核构成，不依赖任何其它语言的产物 |
| D1 | D2 | 格式先定，读写才有判据 |
| D2 | B5 / M2 / M3 | 数据管道与推理侧都从文件取数，读写不统一则结果不可比 |
| C2 | M1 | 特征 fixture 与数值 fixture 共用生成与读取链路 |
| M1 + M2 | M3 | 一致性验收需要样本与推理侧同时就绪 |
| N1 ~ N5 / G2 | D3 | 内核完成才能定发布物与版本策略 |

### 3.3 对拍口径（C2 / C3 的验收标准）

- 整数与布尔：逐元素严格相等。
- 浮点：默认逐元素 `==`（NaN 对 NaN 视为相等、±Inf 按符号相等）；**仅当归约顺序不可避免**（`N3`、`N5`、多线程分块）时允许相对误差 `1e-12`（f64）/ `1e-6`（f32），且必须在该用例的 fixture 元数据里注明 `tolerance`，不得改全局。
- 形状与类型：fixture 记录 dtype 与 shape，对拍时一并断言；不允许隐式转换掩盖差异。
- 边界：每族至少覆盖长度 0 / 1 / 块大小 ±1 / `min_periods` 临界 / 含 NaN 段。
- 文件级：同一份输入数据经各语言读取后，内存中的值必须逐元素一致（这是 `D2` 的验收，与算子对拍分开统计）。

## 4. 执行顺序

批次内可并行，批次间严格按前置。每批的"出口"是下一批的准入条件。

| 批次 | 包含模块 | 前置 | 出口标准（可机械检查） | 状态 |
| --- | --- | --- | --- | --- |
| **M0 契约地基** | C1 → C2 → C3；D1 并行 | 无 | NAME-MAP 覆盖已落地的 Go 公开符号；`DATA-FORMAT.md` 定稿；3 门语言读同一个 npz 且断言通过 | 已完成 |
| **M1 内核对齐** | N1、N2、N3、N6 | M0 | N1 ~ N3、N6 的 fixture 全绿；产出 C++ 相对 Go 的缺口清单 | 已完成 |
| **M2 窗口与向量化** | N4、N5 | M1 | 滚动族 fixture 全绿；AVX2 / NEON 与标量路径对拍通过 | 已完成 |
| **M3 交换格式落地** | D2、D3 | M0（D2）、M1/M2（D3） | Go / C++ / Rust 互读互写同一 CSV：Go 产 Python 读、Python 产 Go 与 C++ 读，值逐元素一致；发布物含版本号 | 已完成 |
| **M4 Rust 定型** | Rust crate、B3 | M1（与 M2 并行） | crate 按 NAME-MAP 暴露符号并通过同一批 fixture；命名与最小参数集对位 | 已完成（B3 属 pandas 仓库，未在本仓） |
| **M5 公式族跨语言** | B1、B2、B3、B4、B6 | M1、M3 | 通达信口径用例在 4 门语言同值；`formula/README.md` 每行状态更新；研究脚本只产 fixture 不与生产耦合 | 进行中（B3 41 个、B2 35 个、Zig 35 个公式；34 个公式已在 Go / C++ / Rust / Zig 四端同值对拍，`LAST` 待统一窗口不足口径） |
| **M6 数据管道** | B5 | M3 | 读 `D1` 格式、按主键覆盖、重复执行幂等；Arrow / Parquet 作为可选扩展单独验收 | 已完成（Arrow / Parquet 未做） |
| **M7 Go 工程侧** | G1、G2 | M1 | Go 服务与管道可独立部署（单二进制、无 Python 运行时）；数值路径完整可用 | 已完成（`cmd/numctl`） |
| **M8 机器学习侧** | M1、M2、M3 | M5、M6 | 训练与推理同一份特征 fixture 一致；同一 ONNX 模型三侧输出一致 | 未开始 |

**关键路径**：`M0 → M1 → M2 → M5 → M8`。Rust 线（`M4`）、格式线（`M3`）、管道线（`M6`）、Go 线（`M7`）在依赖满足后并行插入，互不阻塞。

**排期原则**：

1. 先契约后实现 —— M0 未完成不开工 M1，避免"先写再改名"。
2. 各语言成套交付，不做半套 —— 一门语言要么有完整可运行的数值 + 数据读写 + 发布物，要么不宣称支持；只有"能 import 别人的库"不算交付。
3. 生产核心优先 —— C++ / Rust 的性能敏感内核优先于 Python 侧便利性改造。
4. 每批结束更新本表状态列与对应模块 `.md` 的 §1 路线图 / §5 TODO，两者不一致视为未完成。

## 5. 当前缺口与风险

| 项 | 缺口 | 卡在哪 | 影响批次 | 优先级 |
| --- | --- | --- | --- | --- |

| Rust 覆盖不全 | crate 已通过 129 个 fixture；线性代数、几何、时间与公式族尚未移植 | 按 `NAME-MAP.tsv` 逐行补齐，B3 在 pandas 仓库 | M5 | 中 |
| Go 侧数值与 C++ 有差距 | 缺 AVX-512、迭代器开销、GC 峰值 | 属语言特性，不以牺牲 Go 交付面为代价硬追 | M7 | 低 |
| `LAST` 窗口不足口径不一 | Go 用 `num.Fill(d, 1, true)` 把不足位填 1，C++ / Rust / Zig 取 NaN | 先在 issue 定口径（填 1 还是 NaN），再改实现并补 fixture 行 | M5 | 中 |
| 重复实现风险 | 同名功能可能在两个包各写一套 | C1 已定“权威实现语言”列并由 `name_map_test.go` 校验符号覆盖；CI 自动校验尚未接入 | 全程 | 中 |
| Python 源码外流 | 研究侧代码一旦进入交付链路即等于交出算法 | 交付物只含二进制 + 数据文件；评审项挂进发版检查 | 全程 | 高 |
