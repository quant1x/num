# DATA-FORMAT —— 语言间交换格式（D1）

本文件定义 num / pandas 各语言实现之间**唯一允许的数据交换格式**（[docs/PLAN.md](PLAN.md) §2.3）。
目标不是"能读就行"，而是**同一份文件被任意一门语言的通用读取器直接消费**，不需要为某一方的方言写特例。

格式只承载**数据**，不承载语义：算子口径读 `tests/contract/NAME-MAP.tsv`，模块语义读代码同目录的 `.md`。

## 1. 总则

1. **最小公约数**：基线只依赖 UTF-8 文本与 RFC 4180 引号规则，不依赖任何库的私有方言。
2. **表头即列名**：表头只写纯列名，不带类型、不带命名空间、不带单位后缀。类型由契约表与列语义决定。
3. **列名规则**：`^[a-z][a-z0-9_]*$`（全小写 snake_case），同一文件内唯一，长度 ≤ 64。
4. **空字段即缺失**：缺失值一律写空字段，不用 `NULL` / `NA` / `NaN` / `-` 之类的魔法字符串。
5. **写入幂等**：同一批输入重复导出，产物逐字节一致；按业务主键覆盖写，不向文件尾部追加
   （[CONTRIBUTING.md](../CONTRIBUTING.md) §5.4）。
6. **不做隐式转换**：读取方按列语义解析，解析失败即报错，不静默补默认值。

**表头红线**：`price:double`、`close@f64`、`num.price`、`价格`、`Price` 都不合法。一旦写进文件，
Python / Go 的通用 CSV 读取器就都得为它写特例，跨语言交换立刻失效。

## 2. CSV 基线

### 2.1 编码与行尾

| 项 | 规定 |
| --- | --- |
| 字符集 | UTF-8，**无 BOM** |
| 行尾 | 写入 `LF`；读取接受 `LF` 与 `CRLF` |
| 文件结尾 | 单个换行；不追加空行 |
| 分隔符 | 逗号 `,`；字段内出现逗号、双引号或换行时按 RFC 4180 用双引号包裹，内部双引号写 `""` |

### 2.2 表头

第一行是表头，字段数与数据行一致。列顺序由生产方固定，消费方**按列名读取**，不依赖位置。

```csv
date,open,high,low,close,volume
2026-01-05,10.12,10.55,10.02,10.48,12003400
```

### 2.3 字段类型

| 语义 | 文本形态 | 示例 | 备注 |
| --- | --- | --- | --- |
| 整数 | 十进制，可带负号 | `-42`、`0`、`12003400` | 不接受千分位、十六进制、前导 `+` |
| 浮点 | 十进制或科学计数 | `10.48`、`-0.001`、`1.5e-3` | 不接受 `NaN` / `Inf` 字面量 |
| 缺失 / NaN | 空字段 | `,,` | 读取方按列类型映射为 NaN 或空 |
| 正负无穷 | `inf` / `-inf` | `inf` | 只在这两个词上开口，大小写敏感 |
| 布尔 | `true` / `false` | `true` | 不接受 `1` / `0` / `True` |
| 字符串 | UTF-8 原文 | `沪市A股` | 空字段表示缺失，不是空串 |
| 日期 | ISO 8601 日历日期 | `2026-01-05` | |
| 时间戳 | ISO 8601，可带时区 | `2026-01-05T09:30:00+08:00` | 不带时区时按 UTC 解释 |

浮点的十进制文本必须能被 IEEE 754 双精度**逐位还原**（即 `strtod` 往返一致）；写 `0.1` 而不是
`0.10000000000000001`，写 `1e-9` 而不是 `0.000000001` 都可接受，但同一列的小数位数不要求对齐。

### 2.4 校验与失败

读取方在**打开文件时**完成下列检查，任一不通过即拒绝整份文件并报出行号：

1. 首字节不是 `EF BB BF`（BOM）；
2. 表头每个字段匹配 `^[a-z][a-z0-9_]*$` 且互不重复；
3. 每行字段数等于表头字段数（允许行尾无换行，但不允许缺少字段）；
4. 按列语义解析失败时指出列名、行号与原始文本。

写入方必须保证 `header` 与数据行使用同一列顺序；不允许写"注释行"或"类型行"。

### 2.5 空文件与零行

只有表头、没有数据行是合法文件（零行数据集）。零字节文件不是合法 CSV，读取方应报错而不是当成空表。

## 3. 可选扩展

扩展格式**不是基线**：只在双方显式约定时使用，不得作为默认输出。基线 CSV 始终是回退路径。

### 3.1 JSON Lines（`.jsonl`）

- 一行一个 JSON 对象，UTF-8 无 BOM，`LF` 换行，末尾单个换行。
- 键名规则同 CSV 表头（`^[a-z][a-z0-9_]*$`）。
- 数值用 JSON number；缺失值用 `null`；时间用 ISO 8601 字符串；布尔用 `true` / `false`。
- 不允许行内换行、不允许注释、不允许尾随逗号。

```json
{"date":"2026-01-05","close":10.48,"volume":12003400}
{"date":"2026-01-06","close":null,"volume":0}
```

### 3.2 二进制（`.numb`）

用于大批量数值样本（fixture、特征、权重），头部自带 dtype 与 shape，避免 CSV 的文本解析开销。

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | magic `NUMB`（ASCII） |
| 4 | 2 | 版本，`u16` 小端，当前 `1` |
| 6 | 1 | dtype 码，见下表 |
| 7 | 1 | 维数 `ndim`，`0` 表示标量 |
| 8 | 8 × ndim | 各维长度，`u64` 小端，行主序 |
| 8 + 8×ndim | 余下 | 原始数据，小端，紧密排列无填充 |

| dtype 码 | 类型 | dtype 码 | 类型 |
| --- | --- | --- | --- |
| `b` | bool（1 字节，0/1） | `f4` | float32 |
| `i1` | int8 | `f8` | float64 |
| `i2` | int16 | `u1` | uint8 |
| `i4` | int32 | `u2` | uint16 |
| `i8` | int64 | `u4` | uint32 |
| | | `u8` | uint64 |

规则：

- 字节序恒为小端；大端主机在读写时显式转换。
- 长度为 0 的维度合法；`ndim = 0` 时头部只有 8 字节，数据区是单个标量。
- 文件长度必须精确等于 `8 + 8×ndim + 元素个数 × 元素宽度`，多余或不足都报错。
- NaN / ±Inf 按 IEEE 754 位模式存储，不做文本化。
- 同一目录的 `.numb` 若需要列名，用同名 `.json` 旁挂 `{"columns":["close","volume"]}`；旁挂文件不参与二进制解析。

## 4. 版本与兼容

- 本文件是 D1 的定稿版本；修改列名规则、缺失值约定或二进制头部都属于**破坏性变更**，
  按 [CONTRIBUTING.md](../CONTRIBUTING.md) §9.2 走提案。
- 新增可选 dtype 码属于扩展：旧读取器遇到未知码必须**报错**，不得按长度猜测。
- 各语言的读取器实现登记在 `tests/fixtures/read_*`（C3）与各语言的 `io/` 模块（B5）；
  两侧都必须遵守本文件，不以实现反推格式。
